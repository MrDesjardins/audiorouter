# Soundboard sound library

Part of the [Soundboard tool](soundboard-tool.md) plan. Owner request 2026-10-29:
include about a hundred free sounds the user can pick, next to their own sounds,
with a picker that can sort by category and search. Built-in sounds are short
(under 5 seconds). The user's own sounds may be longer.

Promoted to active work on 2026-10-29; see the [active plan](../active/soundboard.md).

## What "popular" can and cannot mean

The sounds people know best from soundboards are mostly clips from videos, games,
films and television, or from a specific viral recording. Those are copyrighted
and cannot be shipped inside an installer. That rules out, for example, famous
meme clips, movie or TV catchphrases, game or operating-system sounds, and the
original recording of the "Wilhelm scream".

What can be shipped is the **kind** of sound: an air horn, a rimshot, a sad
trombone figure, crickets, applause, a record scratch, a buzzer, a doorbell, a
dramatic sting. The library offers original or properly licensed versions of
those. A person who wants a specific meme clip imports it as their own sound.
This expectation should be stated in the picker ("Want a specific clip? Add your
own") so nobody thinks the library is missing something it is not allowed to
include.

## Licensing rules

Not legal advice; the owner or counsel should confirm before the first release
that bundles the library.

Accepted for bundling:

- **CC0 / public domain**, with the license text checked on the sound's own page
  at the time it is taken.
- **Original sounds made for AudioRouter** (synthesized or recorded by the
  project), released under a license the project controls.

Not accepted in version one:

- **Attribution licenses (CC-BY).** They are allowed in principle but add a
  credit screen to maintain. Skip unless the library cannot reach its size
  without them.
- **NonCommercial, NoDerivatives or ShareAlike licenses.**
- **Sites whose terms restrict redistribution of the files.** Pixabay's terms,
  for example, forbid selling or distributing content on a standalone basis, and
  name audio files; a sound library inside an installer is a collection of those
  files. Mixkit's rules could not be confirmed. Treat both as excluded.
- **Anything uploaded as a copy of a commercial clip**, even on a site that lets
  people upload freely. A CC0 label from an uploader is not proof the uploader
  owned it.

Every shipped file keeps a provenance record (below), and the installer carries a
notices file listing each source and license.

## Where to get the sounds

| Source | What it offers | Status |
| --- | --- | --- |
| [Kenney](https://kenney.nl) audio packs | Interface, impact, digital and similar packs, many of them 100 sounds each, published as CC0 | The Interface Sounds pack is confirmed CC0 (100 OGG files); check the license on every other pack before use |
| [OpenGameArt](https://opengameart.org) with the CC0 filter | Community packs of effects | Verify each item; some are mirrors of other work |
| [Freesound](https://freesound.org) | Very large archive; its API can filter to the CC0 license and to a duration range (for example 0 to 5 seconds) | API needs a free key; confirm the site terms on redistribution before bulk use; per-sound license can differ |
| Wikimedia Commons | Public-domain and CC0 recordings (crowds, applause, animals, nature) | Verify each file's license and recording source |
| Generated by the project | Seeded synthesis script for the classic effects (air horn, buzzer, ding, boing, laser, whoosh, rimshot-style figure, sad horn figure) | License is ours; fully reproducible; good for the "popular kinds" |

Method:

1. Write the target list by category (below) with the specific kind of sound
   wanted, not specific clips.
2. Search the accepted sources for each. For Freesound, use the API with
   `license:"Creative Commons 0"` and `duration:[0 TO 5]`, then listen.
3. For each candidate, open its page, record the author, URL, license and date,
   and keep the original download.
4. Fill gaps with generated sounds.
5. Listen to every file, trim silence, and normalize (below).
6. The owner reviews the final list once; the review is listening, not
   licensing.

The agent can do steps 1, 2 (where the source allows a scripted download), 3, 4
and 5. A Freesound API key is the one thing that needs the owner.

### Getting Freesound access

The "Manage API permissions" page in a Freesound account only lists third-party
apps the person has authorized; it is not where a key is made. A developer key is
requested on Freesound's API credentials page (search the site for "Apply for an
API key", normally under the API documentation): sign in, name the application
("AudioRouter sound library sourcing"), describe it as a non-commercial-use-free
tool that downloads CC0 sounds to review, and submit. The key (a "token") is shown
on that page afterwards.

- With only a token, the API can search and return each sound's license, author,
  duration, tags and **preview** files (a compressed MP3/OGG version). Previews
  are enough to audition and, for sounds under 5 seconds, acceptable as the
  shipped file if the quality is good.
- Downloading the **original** file needs a one-time OAuth2 sign-in as the owner.
  Use it only for sounds the owner has chosen to keep.
- Keep the token out of the repository and out of logs (the AGENTS secrets rule);
  the sourcing script reads it from an environment variable.
- The agent confirms Freesound's current terms of use and per-sound license on
  the page of every sound before it is added.

## Target mix (up to about 100, fewer is fine)

Owner direction 2026-10-29: the library should have what people actually put on a
soundboard, with **several variations of the favorites** (farts, claps, "ta-da"),
because a board with one fart sounds dull and the variations are what make people
keep coming back. A smaller library of good sounds beats a hundred weak ones;
about 80 is an acceptable result.

**Content rules.** No spoken words, no slurs, no sexual sounds, nothing that
imitates a real person. Bodily humor is mild and clearly labelled by its category
name, so a person who does not want it never has to browse it. Each variation gets
a distinct, plain title ("Fart - tiny squeak", "Fart - long rumble") because the
title becomes the caption by default and shows on the button.

## File preparation

- **Length:** 5 seconds at most for built-in sounds; a validation check fails the
  build on anything longer.
- **Level:** normalize all sounds to a common level so no button is suddenly much
  louder than another (a peak ceiling and a similar loudness, measured the same
  way for every file). Pick the numbers in the spike with real listening.
- **Edges:** trim leading silence so the button feels immediate; add a few
  milliseconds of fade at the end to avoid clicks.
- **Channels and rate:** mono unless the sound is meaningfully stereo; 44.1 or 48
  kHz.
- **Format:** the engine currently decodes WAV and MP3 only (symphonia features
  `wav`, `mp3`, `pcm` in `crates/engine/Cargo.toml`). Kenney files are OGG, so
  they are converted. Compare in a spike: WAV (simple, largest, about 10 to 20 MB
  for the whole set), MP3 (smallest, about 3 MB, but check for a gap at the start
  from encoder delay), and FLAC (about half of WAV, requires enabling the
  `flac` feature of the decoder already in use). Choose by size and clean
  starts; plan assumes FLAC or WAV unless the MP3 start is clean.

## Where it lives and how it is used

- **Bundled in the installer** as a read-only resource folder. No download, no
  network access, nothing to approve (the project rules forbid new cloud features
  without approval). A download-on-demand pack is a possible later option and
  would need that approval.
- **Manifest:** `library.json` listing, for each sound: stable id, title,
  category, tags, duration, loudness, file name, source URL, author, license,
  date retrieved and SHA-256.
- **Stable ids.** An id such as `lib:air-horn-01` is written into the saved
  session. Never rename or reuse an id in a later release, or a saved board would
  point at the wrong sound. A sound removed in a future release keeps its id as
  "no longer included" and the slot shows a clear message instead of failing
  silently.
- **Slots refer to built-in sounds by id, not by copying the file** into the
  media store, so a session file stays small and moves between computers without
  carrying audio. A user sound is stored as media, as Audio File does today.
- **Backend owns it.** The API exposes `soundLibrary.list` (the manifest) and the
  node parameter validation accepts a `lib:` id only when it exists in the
  installed library. Adding a library sound is a normal parameter change, so it
  is covered by undo, save and the existing validation.

## The picker

A dialog opened from a slot's **Choose sound** button (and from the empty
"Add sound" row on the card).

- **Search box** at the top, focused on open. Matches title, tags and category,
  as you type, with no layout jump (the result area has a fixed size).
- **Categories** as a list with counts, plus **All** and **My sounds** (files the
  user imported earlier, so one file can be reused on another slot or board).
  Sorting inside a category: by name, with a second option for shortest first.
- **Results** are rows of fixed height: title, category, duration, a **Preview**
  button and a **Use** button. Double-clicking a row uses it.
- **Preview** plays through the app window to the person's normal speakers or
  headphones, **never into the route**. This matters: auditioning a sound must not
  broadcast it to a call. Previews stop when the dialog closes or another preview
  starts. Open question: the window plays decoded bytes it fetches through the API
  (`soundLibrary.read`), or the backend plays the preview to a chosen device.
  Window playback is simpler and enough for 5-second sounds; decide in the
  prototype.
- **Add my own file** in the same dialog, using the existing upload flow, so a
  person never has to know there are two places.
- Keyboard: arrow keys move through results, Space previews, Enter uses, Esc
  closes. Screen reader labels for every control (UI-11).
- Uses the app-wide field style; nothing special for light or high-contrast
  themes. Verify in all three themes, as the other dialogs are.
- The empty-state text, the licensing note ("Built-in sounds are free to use and
  come with the app; see Third-party notices") and the "Want a specific clip? Add
  your own" line sit in reserved space.

## User sounds can be longer

Built-in sounds are capped at 5 seconds; the user's are not. The existing upload
limit is 64 MiB per file (`MAX_AUDIO_MEDIA_BYTES`). The Soundboard decodes every
slot into memory when the session is prepared, so long files need a budget:

- Proposed first-version limits: **120 seconds per slot** and a **total decoded
  budget for the board** (for example 256 MB). Tell the user at upload, with the
  actual numbers, instead of failing at Play.
- A long sound needs a way to stop it: the per-slot **Stop** control in
  Properties and on the card, and `soundboard.stop` with a slot.
- Longer than that (a full song, a long podcast clip) would need streaming from
  disk instead of decoding up front. That is more work and is **not** in the
  first version; Audio File remains the tool for long playback.

## Provenance and checks

A script under `tools/soundboard/` (checked in CI) verifies the library:

- every file in the folder has a manifest entry, and every entry has a file;
- the SHA-256 matches;
- the license is on the allow-list (CC0, public domain, original);
- duration is 5 seconds or less;
- level is within the normalization range;
- ids are unique and none from a previous release has disappeared or changed
  (compare to the last released manifest).

The installer includes a **third-party notices** file generated from the manifest,
and Settings shows a link to it.

## Validation

| Check | Environment |
| --- | --- |
| Manifest, license, duration, level and id-stability checks | Portable, CI |
| Every library sound decodes with the engine decoder | Portable |
| Slot with a library id plays and mixes; a missing id is reported, not silent | Portable unit test |
| Picker: search, category filter, sort, preview, use, keyboard use; fixed result area; three themes | jsdom plus Edge |
| Preview never reaches the route | Test with a running route and a capture of the route output |
| Installer includes the folder and the notices; an installed copy lists and plays a sound | Windows, built exe |
| Listening review of the final set by the owner | Attended |

## Risks

- **Fewer good free sounds than expected for a category.** Generated sounds fill
  the gaps; the count of 100 is a target, not a requirement.
- **A source changes or removes a sound later.** The provenance record keeps the
  original URL, author and date, and the file itself is kept in the repository.
- **A license was mislabeled by an uploader.** Prefer well-known packs and
  recordings whose origin is clear; keep the evidence.
- **Installer size grows.** Measured in the format spike; the worst case is
  about 20 MB.
- **Id churn breaks saved boards.** Covered by the stable-id rule and check.

## Decisions (owner, 2026-10-29)

1. CC0, public-domain and original sounds only for version one.
2. Bundled in the installer; no download.
3. 120 seconds per slot and a total decoded budget for the board are accepted.
