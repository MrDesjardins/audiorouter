## Build, upload and artifact identity

Annotated tag `v0.0.22` on `097c0354` (main), pushed. Built in
`.worktrees/release-0.0.22` (detached at the tag, porcelain clean; `npm ci`
for contracts and UI) with `create-draft-release.ps1 -Tag v0.0.22 -AppOnly`
from bash with OS-level redirection (log `target/release-022-build.log` in
that worktree).

Two attempts stopped before any upload:

1. `target/releases` did not exist; the script requires the output parent.
2. `tools/m06-vst3-sdk/install.ps1` derived Git's root as two levels above
   `git.exe`. Started from Git Bash, `git` resolves to
   `Git\mingw64\bin\git.exe`, so it looked for bash in `Git\mingw64` and
   threw "Git for Windows bash/cygpath is required". The SDK (ignored by
   Git) was installed at its pinned revision `3cdf9ca5` with `Git\cmd`
   first on PATH, and the build was rerun the same way. The script now walks
   up to the folder holding `usr\bin\bash.exe` (`2694cbad`, tested from both
   PATH orders); it is not in the tag.
