# AudioRouter 0.0.28

This release fixes the two Play failures reported in
[issue #123](https://github.com/MrDesjardins/audiorouter/issues/123). It also
includes the UI and UX improvements merged since 0.0.27.

## Fixes from issue #123

- **An app behind a Duck in a Mixer now plays.** A route with a microphone
  into a Mixer and Firefox → Duck → Mixer was refused with "Play can capture
  firefox.exe only when it is the route's only enabled source". Play now finds
  the application behind the Duck.
- **A mono input on a stereo audio interface now plays.** An Input Device set
  to one channel and bound to a stereo interface was refused with "capture
  endpoints must exactly match the physical-input channel/rate/float32
  contract". AudioRouter now reads both interface channels and folds them into
  the input's one channel. It follows the input's Channels choice: left only,
  right only, or both mixed.
- **Clearer device errors.** If an input device still cannot be used, the
  message names the input and the reason: an output was chosen instead of an
  input, the device is not shared as float audio, its sample rate is out of
  range, or its channel count does not match.
- **Apps are found again after a restart.** An application source picked by
  goal or by `.exe` finds the running app when you press Play, even after
  a PC restart gives it a new process ID. Before you press Play it says
  "Waiting for Play".

## UI and UX improvements

- **Settings search, a simpler tray, and messages that close on their own.**
  A lost audio device shows as an error that stays on screen, in plain words.
- **Number fields** show their range in words. An out-of-range value is shown
  and explained instead of being silently reverted.
- **Keyboard:** place a tool you added from the keyboard with the arrow keys,
  and press Escape to cancel a card or connection drag. Escape also returns to
  the tool that added a card.
- **Readability:** text contrast is checked against WCAG AA in the dark, light
  and high-contrast themes. AudioRouter warns when a custom theme makes text
  hard to read. Clipped text in the device apps list is fixed, and the tool
  guide link has a larger target.
- **Reduced motion** is respected in scripted scrolls.
- **Tabs, goals, compare, palette and history**, with Session usable while
  history loads. Pinned tools show in the top rows at once.
- **Empty routes and imports:** opening an empty route no longer crashes the
  window. A save rejected because an audio import is not finished explains why.
- **Tool guides:** the Test Signal buttons are named for the tone, and the
  guides are refreshed for the new Properties panel.
- **Security:** MCP authorization and pipe identity are fixed, and session
  export now asks for consent.

Windows 11 x64. The app and installer are unsigned. This is still an
experimental app-only prerelease, not a fully M08-qualified release. It does
not include or install an AudioRouter virtual audio driver, and it does not
change Windows default audio devices. WebView2 must be present or installed by
setup.

Close AudioRouter before upgrading. Back up your configuration and recordings,
and keep the 0.0.27 installer for rollback. This version does not change the
session or database format.

Not yet qualified for this release: live playback through a stereo audio
interface, the full hardware matrix, long-run continuity, accessibility, and
install/upgrade/rollback. The known `/repair` installer limitation from 0.0.26
remains.
