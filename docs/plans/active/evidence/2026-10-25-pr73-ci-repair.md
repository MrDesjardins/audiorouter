## Repair and preserved coverage

Shared browser verification now builds all four suite entry pages into
`target/browser-acceptance-ui` before launching Edge, using the normal Vite
production chunking. The full CI profile inherits development discovery and
failure policy, replacing only its server with Vite preview. This removes the
large dev module graph and HMR requests from the long acceptance run. It does
not catch/reload failed pages, increase timeouts or turn retried passes green.
Development and focused production commands remain available. Fixture output
never replaces `ui/dist` embedded in the shell.

The nightly startup job checks the separately installed WebView2 runtime and
retains before/after registration and session evidence. If absent on the
disposable runner, it downloads Microsoft's Evergreen bootstrapper, requires a
valid Microsoft Authenticode signature, records SHA-256, installs with a bounded
wait and verifies registration. Automatic installation is refused outside
GitHub Actions. This supplies a prerequisite; it does not prove runtime absence
caused the original failure. Both packaged uploads now retain bounded application
JSONL/panic logs. Profiles and databases remain excluded.

Sources: [Microsoft runtime detection and distribution](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution),
[official bootstrapper example](https://github.com/MicrosoftEdge/WebView2Samples/blob/main/SampleApps/WebView2APISample/AppWindow.cpp),
[failing runner image inventory](https://github.com/actions/runner-images/blob/win25-vs2026/20261021.278/images/windows/Windows2025-VS2026-Readme.md).

not sufficient evidence of WebView2's presence or absence.
