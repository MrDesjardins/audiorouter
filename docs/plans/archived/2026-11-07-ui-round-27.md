## Implementation and decisions

The real Windows input path reproduced browser Find (Ctrl+F), Print (Ctrl+P)
and Reload (F5 resetting Session to Tools) in the old E06ADFA6 release.
`webview_keys.rs` now disables browser accelerators through native WebView2
Settings3, reads the setting back and logs a bounded internal shell record.
The COM interfaces remain on Tauri's UI thread, with documented lifetimes.
Unsupported-runtime failures are logged while leaving the editor usable.
Existing WebView2 COM ABI versions became direct Windows-only dependencies;
no package was upgraded. This internal shell setting adds no public method,
node setting or tool control, so API/MCP schemas and Properties guides are
unchanged.

The packaged smoke requires a successful disabled read-back from the current
PID at or after its launch time, including restart. The old binary fails that
specific assertion and quits cleanly. This guards against missing setup,
failed read-back and stale/reused-PID evidence.

New browser suites exercise actual select keys, long duplicate device names,
draft-only selection and Escape focus. The density inventory derives Settings
pages from the app catalog and checks 22 destinations plus 32 expanded addable
tool kinds at 1280x720 and 640x360, in three themes. It checks horizontal
containment, 24px button targets and unclipped button captions; it is not an
exhaustive spacing or real Windows scaling qualification.

`report-bundle.mjs` records production chunk ownership without replacing
`ui/dist` or recursively cleaning caller-selected directories. The production
entry is 599,241 bytes. Five unchanged-binary startup samples measured fresh
profiles at 1718/1191/1099/1136/1109 ms and restarts at
1104/1342/1147/1240/1162 ms. These stopped three-card local samples are not
OS-cold measurements. No demonstrated startup bottleneck justified moving
chunk boundaries; the warning remains visible and its threshold is unchanged.
