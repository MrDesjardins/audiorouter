01 / Understand

How it works.

Each plugin defines its own automatable controls; scanning discovers metadata, while adding and preparing a plugin is a separate action.

Source→Chosen VST effect→Meter → Output

Use it in AudioRouter

  1. Scan an explicitly chosen installed x64 plugin directory and inspect a supported result.
  2. Add the intended exact plugin to the draft and wire it into the branch.
  3. Save and Play, then verify plugin running telemetry and the downstream meter.
  4. Use the plugin-defined parameter ranges and matched-level Bypass comparisons.

What success looks like

The chosen plugin identity and its own parameter metadata determine the controls. A scan result alone does not prove successful live processing.

If it does not work

If it faults, inspect the error and recover deliberately. Protected voice paths remain silent rather than silently bypassing a failed processor.

Select the node to open Properties. Click its name to rename it. While playing, supported parameter-only edits save after a short pause. For structural edits, use Save when the canvas marks a change. Enabled and Bypass are distinct live controls; see the in-app help for their behavior.

  1. Use Bypass for a deliberate dry comparison.

These are starting points. Compare at a comfortable monitoring level and adjust for your own source.

05 / Troubleshooting

Common mistakes.

  • Scan completion does not mean plugin code has been loaded or has processed audio.
  • A running session can contain a silent failed plugin path.
  • Do not use another plugin’s values as though parameter IDs or scales were shared.
