01 / Understand

How it works.

Click Choose an application source to open the picker, then select a running application. AudioRouter remembers the application's identity, not just its current PID. When the app closes, capture waits; when it starts again with a new PID, AudioRouter finds the matching application again. If more than one matching instance is running, choose the one you want. Normal application playback continues.

Chosen app process→Application Capture→AudioRouter route

Use it in AudioRouter

  1. Open the application and make it play audio.
  2. Refresh the running-app list and choose the intended process in Tools.
  3. Add the source, connect it to your processing/output, Save and Play.
  4. Check the source meter while the selected app makes sound.

What success looks like

The selected application's audio enters the route independently of a whole-output loopback.

If it does not work

A restarted app can have a new process identity. Refresh and select it deliberately; check whether the target app is actually producing sound.

Select the node to open Properties. Click its name to rename it. While playing, supported parameter-only edits save after a short pause. For structural edits, use Save when the canvas marks a change. Enabled and Bypass are distinct live controls; see the in-app help for their behavior.

04 / Examples

Example setups.

Example 1

Separate game and voice

  1. Add an Application Capture for the game and a Physical Input for your microphone.
  2. Route each to its own processing chain.
  3. Combine them only where you want a mix.
Example 2

Troubleshoot a quiet app

  1. Check whether the node says app closed, ambiguous, unsupported, or connected.
  2. Start audio in the chosen application and refresh its inventory.
  3. Confirm the actual node meter, rather than assuming connected means audible.

These are starting points. Compare at a comfortable monitoring level and adjust for your own source.

05 / Troubleshooting

Common mistakes.

  • Capturing an app does not mute its normal speaker playback; duplicate monitoring can result.
  • Two indistinguishable verified instances require deliberate selection.
  • Protected or unusual applications are not guaranteed to capture.
